# Riftwatch Boot

Client-only early loading screen `rift_boot` of the Riftwatch modpack (Minecraft 1.21.1, NeoForge 21.1.255, FancyModLoader 4.0.45). It replaces the red NeoForge loading window with the fox by the Riftwatch scene of the title screen: the sky shader with the local time of day and the moon phase, the seam and the honeycomb floor, the wordmark and the tagline at their title screen positions, copper progress bars, the memory bar, the last loader messages, the versions and a turning day dial.

All rights reserved; `LICENSE` names the permitted use (the unmodified jar in the Riftwatch modpack and on its Modrinth pages).

It is not a mod. The jar sits in `mods/` and FancyModLoader loads it into its service layer, because `META-INF/services` registers an `ImmediateWindowProvider` and a `GraphicsBootstrapper`. It opens no network channel, so servers never see it.

## How It Works

| Class | Role |
|---|---|
| `RiftwatchBootstrapper` | Runs before the window opens; switches `earlyWindowProvider` in `config/fml.toml` from `fmlearlywindow` to `riftwatch` |
| `RiftwatchWindow` | Subclass of NeoForge's `DisplayWindow` named `riftwatch`: keeps the window, the context handoff, the crash window and the loading overlay, sets the dark colour scheme (and a dark letterbox colour), skips the Mojang logo and replaces the element list after NeoForge's render setup |
| `SceneElements` | Takes the place of NeoForge's element list; sizes the frame to the window, draws the scene instead of NeoForge's elements and falls back to them (and to the 854x480 frame) for good after the first failure (logged as `Riftwatch boot screen failed`) |
| `BootScene` | Draws the scene at the window's own framebuffer size (no letterbox, no upscaling) with the title screen's GUI scale (`guiScale` and `forceUnicodeFont` from `options.txt`, computed like Minecraft), first on the early render thread, later inside NeoForge's loading overlay until the title screen |
| `PixelFont` | NeoForge's Monocraft rasterized at one font pixel per pixel and drawn with nearest filtering at the GUI scale, so text matches the size and sharpness of the menu text |

No code of FancyModLoader is copied; the classes extend and call its public API and use private fields by reflection: `DisplayWindow` (`colourScheme`, `renderScheduler`, `elements`, `context`, `framebuffer`, `fbWidth`, `fbHeight`, `fbScale`, `window`, `windowTick`) and `EarlyFramebuffer` (`texture`, `context`). A window resize reallocates the existing frame texture instead of creating a new one, so no texture name is freed while Minecraft's texture cache may still hold it.

Resources in `src/main/resources/net/riftwatch/boot/`:

| File | Source |
|---|---|
| `transit.glsl` | Generated by `scripts/build-title-screen` of `riftwatch-modpack` (`title-screen/transit.glsl`: the title screen sky without the day HUD); copy it again after every change of `title-screen/sky.glsl` |
| `wordmark.png`, `wordmark_glow.png`, `tagline.png` | `config/fancymenu/assets/riftwatch/` of `riftwatch-modpack` |

## Build

| Command | Purpose |
|---|---|
| `./gradlew build` | builds `build/libs/rift_boot-<version>.jar` (`-Xlint:all -Werror`) |

JDK 21 is selected by the Gradle toolchain. FancyModLoader, LWJGL and SLF4J are compile-only dependencies; the game provides them.

## Removal

Delete the jar and set `earlyWindowProvider = "fmlearlywindow"` in `config/fml.toml`. Without the second step NeoForge finds no provider named `riftwatch` and starts without an early window.

## Updates

Every NeoForge or FancyModLoader update needs a check of `DisplayWindow` and `EarlyFramebuffer` (the private field names, `initRender`, `renderThreadFunc`, `paintFramebuffer`, `setupMinecraftWindow`, `EarlyFramebuffer.draw`), of `NeoForgeLoadingOverlay` (`newInstance`, the frame fit in `render`) and of `Monocraft.ttf` in the earlydisplay jar before the pack moves.
