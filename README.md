# Riftwatch Boot

Client-only early loading screen `rift_boot` of the Riftwatch modpack (Minecraft 1.21.1, NeoForge 21.1.255, FancyModLoader 4.0.45). It replaces the red NeoForge loading window with the fox by the Riftwatch scene of the title screen: the sky shader with the local time of day and the moon phase, the seam and the honeycomb floor, the wordmark and the tagline at their title screen positions, copper progress bars, the memory bar, the last loader messages, the versions and a turning day dial.

All rights reserved; `LICENSE` names the permitted use (the unmodified jar in the Riftwatch modpack and on its Modrinth pages).

Since 0.1.1 it also keeps the pack up to date at every start, in every launcher (Section Updater).

It is not a mod. The jar sits in `mods/` and FancyModLoader loads it into its service layer, because `META-INF/services` registers an `ImmediateWindowProvider`, a `GraphicsBootstrapper` and an `ITransformationService`. It opens no network channel to game servers, so servers never see it; the updater only makes HTTPS requests to `riftwatch.net` and the download hosts the pack names.

## How It Works

| Class | Role |
|---|---|
| `RiftwatchBootstrapper` | Runs before the window opens; switches `earlyWindowProvider` in `config/fml.toml` from `fmlearlywindow` to `riftwatch` |
| `RiftwatchWindow` | Subclass of NeoForge's `DisplayWindow` named `riftwatch`: keeps the window, the context handoff, the crash window and the loading overlay, sets the dark colour scheme (and a dark letterbox colour), skips the Mojang logo and replaces the element list after NeoForge's render setup |
| `SceneElements` | Takes the place of NeoForge's element list; sizes the frame to the window, draws the scene instead of NeoForge's elements and falls back to them (and to the 854x480 frame) for good after the first failure (logged as `Riftwatch boot screen failed`) |
| `BootScene` | Draws the scene at the window's own framebuffer size (no letterbox, no upscaling) with the title screen's GUI scale (`guiScale` and `forceUnicodeFont` from `options.txt`, computed like Minecraft), first on the early render thread, later inside NeoForge's loading overlay until the title screen |
| `PixelFont` | NeoForge's Monocraft rasterized at one font pixel per pixel and drawn with nearest filtering at the GUI scale, so text matches the size and sharpness of the menu text |

No code of FancyModLoader is copied; the classes extend and call its public API and use private fields by reflection: `DisplayWindow` (`colourScheme`, `renderScheduler`, `elements`, `context`, `framebuffer`, `fbWidth`, `fbHeight`, `fbScale`, `window`, `windowTick`) and `EarlyFramebuffer` (`texture`, `context`). A window resize reallocates the existing frame texture instead of creating a new one, so no texture name is freed while Minecraft's texture cache may still hold it.

Resources in `src/main/resources/net/riftwatch/boot/`:

| File | Source |
|---|---|
| `transit.glsl` | Generated by `scripts/build-title-screen` of `riftwatch-modpack` (`title-screen/transit.glsl`: the title screen sky without the day HUD); copy it again after every change of `title-screen/sky.glsl` |
| `wordmark.png`, `wordmark_glow.png`, `tagline.png` | `config/fancymenu/assets/riftwatch/` of `riftwatch-modpack` |

## Updater

`UpdateService` is an `ITransformationService`. ModLauncher calls its `initialize` after the early window is up and before NeoForge scans `mods/`, so mod jars replaced there load in the same start. It works only for the production client (launch target `forgeclient`) and never stops the game: every failure is logged and the installed pack starts.

Start sequence:

1. Finish or roll back an interrupted update (`journal.json`).
2. Stop if `config/riftwatch-updater.toml` says `enabled = false` (written once with `enabled = true`).
3. Read the installed version from `config/riftwatch/pack.json` (the pack marker); without it the updater stays idle.
4. Fetch `https://riftwatch.net/downloads/modpack/latest.json` (3 s budget). Only a newer version is installed, never an older one.
5. Check Minecraft and NeoForge of the new version against the running ones (launch arguments `--fml.mcVersion`, `--fml.neoForgeVersion`); a loader change is left to the launcher.
6. Download the `.mrpack`, check its sha512 and its Ed25519 signature (`.mrpack.sig`, two public keys built in) and read its policy `config/riftwatch/updater.json` (`mode` `observe`, `apply` or `off`; a pack without a policy counts as `observe`).
7. Plan: every file of the new pack is `pack` (replaced when it changed), `settings` (merged per key) or `player` (created once, never touched again). Built-in `player` files: `options.txt`, `servers.dat`, `config/fml.toml`, `config/riftwatch-updater.toml`, `config/fancymenu/user_variables.db`, `shaderpacks/*.txt`; files under `config/` without a rule are `settings`, everything else `pack`.
8. `observe`: log the plan and the settings merge, change nothing. `apply`: download into `riftwatch/updater/staging/` (4 at a time, sha512 checked), write the journal, move the files, keep the replaced ones in `backup/<old version>/`, merge the settings, write the state.
9. If a service layer jar changed (this jar, or any jar that registers one of the six loader services), the window counts down 8 s and the game closes; the next start runs the new jar. Otherwise the start continues with the new pack.

Rules that keep the player's files:

| Case | Rule |
|---|---|
| Settings key changed by the player | kept; a key the player never touched follows the pack; keys only the player has stay; new keys of the pack are added in their section |
| Settings reset by a launcher update | restored from the snapshot in `riftwatch/updater/settings/` (written after every merge and when the game exits) |
| Pack file edited by the player, unchanged in the pack | kept (mod jars excepted) |
| Mod disabled by the player (`.jar.disabled`) | updated as `.disabled`, also when the file name of the new version differs (same Modrinth project or GitHub repository) |
| Shader pack, resource pack or optional file the player deleted | stays deleted |
| Mod the player added | never touched; only jars whose hash belonged to an earlier pack version are removed |
| Saves | never touched; no pack path may point into `saves/` or `riftwatch/updater/` |

Formats merged per key: TOML (`.toml`, multi-line values are left alone), `key=value` properties (`.properties`), `key = value` lines (`.cfg`), JSON (`.json`, by leaf path). Line ending, byte order mark, comments, order and indentation stay as the file had them. Any other format follows whole file rules: replaced only if the player never changed it.

Downloads come only from `riftwatch.net`, `cdn.modrinth.com`, `github.com`, `objects.githubusercontent.com` and `release-assets.githubusercontent.com` over HTTPS. The request carries no player data, only the user agent `Riftwatch-Updater/<rift_boot version> (pack <installed version>)`. Window texts are English ASCII; the log uses the logger `RIFTWATCH-UPDATE`.

Local state per instance in `riftwatch/updater/`: `state.json` (installed version, sha512 of every pack file, files the player removed), `packs/` (the signed pack of the installed version, the base of the next merge), `settings/` (snapshots), `backup/<version>/` (files the last update replaced), `staging/` and `journal.json` only during an update.

For a test against another source, start the game with `-Driftwatch.updater.source=<base url>`; that host is added to the allowlist and may use plain HTTP. The signature check stays.

| Class | Role |
|---|---|
| `UpdateService` | Entry point, builds the updater with the real window, source and keys |
| `PackUpdater` | Start sequence above, messages, restart countdown |
| `PackSource`, `PackSignature`, `PackArchive` | `latest.json`, downloads with allowlist and size and hash checks, Ed25519 keys, `.mrpack` index and overrides |
| `UpdatePolicy`, `UpdatePlanner`, `UpdatePlan` | File classes and the plan of installs and removals |
| `SettingsStep`, `SettingsMerge`, `LineSettings`, `JsonSettings` | Three way merge per key with reset detection and snapshots |
| `Journal`, `UpdateState`, `FileOps`, `InstancePaths` | Crash safe moves, local state, path rules |
| `ServiceJars` | Tells service layer jars apart (`module-info` provides or `META-INF/services`) |
| `Background`, `WindowDisplay` | Runs network and disk work on a daemon thread while the window keeps drawing, with a stall watchdog |

## Build

| Command | Purpose |
|---|---|
| `./gradlew build` | runs the unit tests and builds `build/libs/rift_boot-<version>.jar` (`-Xlint:all -Werror`) |
| `./gradlew test` | unit tests only: settings merge with real pack files, rules, signatures, and end to end updates against a local HTTP server |

JDK 21 is selected by the Gradle toolchain. FancyModLoader, ModLauncher, LWJGL, SLF4J and Gson are compile-only dependencies; the game provides them.

## Removal

Delete the jar and set `earlyWindowProvider = "fmlearlywindow"` in `config/fml.toml`. Without the second step NeoForge finds no provider named `riftwatch` and starts without an early window. The folder `riftwatch/updater/` and `config/riftwatch-updater.toml` can be deleted too.

To keep the boot screen but stop the updates, set `enabled = false` in `config/riftwatch-updater.toml`.

## Updates

Every NeoForge or FancyModLoader update needs a check of `DisplayWindow` and `EarlyFramebuffer` (the private field names, `initRender`, `renderThreadFunc`, `paintFramebuffer`, `setupMinecraftWindow`, `EarlyFramebuffer.draw`), of `NeoForgeLoadingOverlay` (`newInstance`, the frame fit in `render`) and of `Monocraft.ttf` in the earlydisplay jar before the pack moves. For the updater: the `ITransformationService` order (`initialize` before the game layer scan), the six service names in `ServiceJars`, `StartupNotificationManager` (`addModMessage`, `prependProgressBar`), `FMLLoader.progressWindowTick` and the launch argument names.
